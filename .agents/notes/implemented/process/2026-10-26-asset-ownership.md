# Agent Note: 资产归属

Status: implemented

## Problem

模板被复制成多个独立仓库后,每个项目的文件混在一起:技能、门禁、防御模式属于模板,笔记、架构与业务代码属于项目,`AGENTS.md`、`package.json`、CI 与预算清单各占一半。没有成文的分类时,模板使用者不知道哪些文件可以直接改、哪些改动会在模板更新时变成冲突;实际后果是派生项目漏掉了技能与防御模式的更新,而混合文件被整段重写。

## Decision

新增 [资产归属](../../../../docs/asset-ownership.md),把仓库文件分成三类并写清改动方式。

- **框架资产**:技能、防御模式、门禁实现、lint 与 hooks;项目内不改,扩展用新文件,通用改进向上游提 PR。
- **混合资产**:`AGENTS.md`、开发/测试指南、`package.json`、CI、tsconfig 与测试配置、预算清单;保留模板段落与键,只追加项目内容。
- **项目资产**:Agent Notes、架构、README、`apps/`、`packages/`、环境与数据;直接改,模板更新不覆盖。
- 文档从 [README](../../../../README.md) 的文档列表、[开发指南](../../../../docs/development.md) 开头与根 [AGENTS.md](../../../../AGENTS.md) 的仓库布局进入;预算清单增加该文件的条目。

## Alternatives considered

- **在每个文件头写归属注释** —— 否决:注释会进入源码与文档正文,增加噪音,而且移动文件后容易过期;集中一页更容易维护与链接。
- **只写进 AGENTS.md** —— 否决:AGENTS.md 是站立命令,需要短;分类表与路径对照放进去会挤掉必须常驻的规则。
- **先做自动同步工具再写文档** —— 否决:同步工具依赖明确的归属边界;先写清分类,后续脚本才有输入。

## Consequences

- 分类是约定而不是门禁:归错类不会立即失败,但模板更新时会以冲突或漏更的形式暴露。
- 目录结构变化时,本页与预算条目要同 PR 更新,否则文档会指向不存在的路径。
- 混合资产仍需人工或脚本按结构合并;本页只给出边界,不代替同步工具。
- 派生项目在下次复制或同步模板时获得本页;已有的项目不会自动更新。
- 模板自身的 Agent Notes 记录模板决策,不属于可下发资产,不随版本复制进项目。
