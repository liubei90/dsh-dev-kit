# 防御模式(Defensive patterns)

涉及生命周期、并发、子进程、异步 teardown 的代码,先读本页。这些是这类 bug 的常见类别与对策。

## 生命周期

- **注册必须可清理**:每个 listener、订阅、连接、定时器、worker 的注册返回 disposer;dispose 幂等;HMR/热重载时旧注册被清理。
- **所有权明确**:谁创建谁释放;跨模块传引用时说明借出还是持有。

## 并发

- **发布前消除竞态**:状态先就绪再对外可见;await 期间可被取消的路径处理取消。
- **回调包含**:回调内错误独立上报,不让一个回调的异常破坏其他回调。

## 子进程与外部进程

- **等待真实完成信号**:kill/close 之后 await 退出信号,不能只调用不等待。
- **超时兜底**:外部进程必须有超时;超时后清理进程树。

## 异步 teardown

- **释放到静默**:teardown 停止新回调、断开 listener、恢复全局钩子、终止自有工作,并等待子进程/服务关闭完成。
- **失败路径也清理**:注册后立即登记清理,断言失败也要释放资源。

## 空 catch

- 空的 `catch` 必须注释它吞掉了什么、为什么没有别的能到达这里;`try` 保持单语句。
