# 架构(Architecture)

本文件是模块地图:应用如何组成、模块如何关联、扩展点在哪。**改架构前先读本页**,重大结构决策要写 Agent Note。

## 组成(当前占位,随实现填充)

```
apps/web  → 页面/组件/客户端状态 → 经 HTTP 调用 apps/api
apps/api  → HTTP 路由 → 服务层 → 数据访问(DB/外部服务)
packages/shared → 前后端共享的类型、DTO、校验、常量(契约单一来源)
```

## 分层规则

- 控制器薄、服务层承载业务、数据访问隔离在仓储/DAO。
- 依赖方向单一:`apps/*` → `packages/shared`;`apps/*` 之间的直接依赖禁止,共享一律经 `packages/shared`。
- 每个模块只通过自己的入口暴露能力;跨模块调用走入口,不深入对方内部文件。
- 前端状态归属清楚:服务端数据经请求层获取并缓存,纯 UI 状态留在就近组件持有。
- 边界输入要校验:HTTP 请求体、查询参数、外部服务响应在进入业务层前解析为类型化值。
- 新能力先写 [proposed Agent Note](../.agents/notes/README.md),评审后再实现。

(随项目演进填充:认证中间件、数据源 provider、事件总线、后台任务、前端路由与模块等。)
