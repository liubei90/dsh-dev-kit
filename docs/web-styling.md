# Web 样式(Web styling)

浏览器端的样式所有权与组件规则。当前 `apps/web` 仍是占位实现，没有 React、CSS 或设计 token，因此本文只写**不依赖具体实现**的原则，并在最后给出设计系统落地后的迁移路线。它是约束未来实现的标准，不是对现状的描述。

## 所有权

- 样式分两层：**主题层**（颜色、字体、圆角、间距的语义 token 与明暗主题）与**组件层**（组件自己的布局与外观）。主题层由专门的主题包拥有，组件层放在组件旁边。
- 功能代码只消费语义 token，不直接写主题值；新增颜色、字号或间距前，先找现有的 token 或同类组件已在用的值。
- 主题选择器（`.dark`、`[data-theme]`）只出现在主题层；功能组件的 CSS 不写明暗分支。

## 组件规则

- **复用先于新增**：优先扩展现有组件、容器或交互；新建平行的按钮、菜单、卡片是最后手段。
- **样式就近**：组件样式与组件同目录（`Component.module.css`）；全局样式只放重置、字体与主题变量。
- **内联样式不承载主题**：内联样式只允许传组件局部的自定义属性值；颜色、字体、间距不写进 `style={{}}`。
- 类名组合用 `clsx` 或等价工具，不手拼字符串。
- 不引入组件库或原子化 CSS 框架（Tailwind 等），除非设计系统明确引入并把决策记进 Agent Note。

## 与系统无关的视觉基线

- **对比度**：每对前景/背景在明暗两套主题下都要可读；正文不使用低于可读要求的对比度。
- **字体层级**：页面内字号种类尽量少，同层级内容同一字号；字重不超过 500，强调用字号或颜色。
- **间距**：相邻元素有明确间距；平行元素对称；不一致的间距先怀疑漏了共享值。
- **圆角与描边**：同一类表面共用一套圆角与描边，不为单个组件新造一套。
- **动效**：只用于表达状态变化；尊重 `prefers-reduced-motion`。

## 响应式与输入能力

- 布局、截断、标题换行、icon-only 控制、hover 与触摸、文本框 16px 下限，遵循 [responsive-ui](../.agents/skills/responsive-ui/SKILL.md)。
- 用 CSS 媒体特性（`prefers-color-scheme`、`(hover: hover)`、`(pointer: coarse)`）判断，不解析用户代理。

## 可访问性与反馈

- 交互元素可聚焦、有可见焦点、有可访问名称；选中、展开、禁用等状态与视觉一致。
- 错误与空态用文字表达，不只靠颜色；反馈面的选择遵循 [client-ui-ux](../.agents/skills/client-ui-ux/SKILL.md)。

## 评审清单

- 新增的颜色、字号、间距来自既有 token 或已存在的同类值吗？
- 明暗两套主题都验证过吗？
- 复用了已有组件，还是新增了平行实现？
- 有内联样式承载主题值吗？
- 焦点、hover、触摸与窄视口都验证过吗？

## 设计系统落地后的迁移路线

按顺序执行，每一步都能独立验收：

1. **建 token 层**：新建主题包（例如 `packages/ui/theme`），提供 `tokens.css`（原始色阶、间距、圆角、字号）与语义别名（`--app-color-text`、`--app-surface-raised` 等），导出明暗主题选择器。验收：只改 token 就能整体切换主题。
2. **建基础组件**：按钮、输入、菜单与浮层、卡片、表格按需落地，每个组件自带 `*.module.css` 并与 token 对齐，同时建立组件目录。
3. **迁移现有页面**：逐页替换字面量与内联样式，每页迁移后对比明暗两套主题。
4. **把规则变成门禁**：新增 `verify-web-styling` 或等价 lint 规则——功能 CSS 不允许字面量颜色（token 文件除外）、不允许 `style={{ color: … }}`、主题选择器只能出现在主题包；先用 allowlist 收敛存量，再逐项清零。
5. **更新本文**：把"所有权"里的占位路径换成真实包名，把"迁移路线"改写成"当前状态"；同步 `docs/AGENTS.md` 的层级表与文档预算。
6. **记录决策**：引入设计系统属于架构决策，写一篇 `implemented/architecture` 的 Agent Note，记录选型、被否决的备选与迁移成本。
