# 服务端与 API 边界

适用于 `apps/api` 的路由、服务层、数据访问与外部调用。

## 请求边界

- **在边界校验。** body、query、params 与 header 在路由边界做运行时校验,校验失败返回结构化的 4xx;服务层与数据层可以信任已经过校验的值。
- **鉴权在做决定的那个操作里执行。** 中间件顺序、路由分组与包装器都不是强制;直接调用与替代调用方绕过它们时,越权仍然必须被拒绝。权限判断要能追到真正执行操作的那一处。
- **状态码语义正确。** 客户端输入错误是 4xx,服务端缺陷是 5xx;框架产生的错误(坏 JSON、不支持的 content type、超限载荷)不能被统一处理成 500。

## 分层

- **控制器薄。** 路由只做解析、鉴权、调用与响应映射;业务规则在服务层;SQL 与外部 I/O 隔离在仓储/客户端。
- **业务规则住在自己的模块。** 通用编排(路由分发、事务、日志)不吸收业务分支;业务能力通过注册面或投影数据接入,而不是在共享层里加 `if`。
- **共享契约是单一来源。** 请求与响应类型、校验与错误码来自 `packages/shared`;服务端与客户端都不复制模型定义。

## 数据

- **SQL 一律参数化。** 禁止字符串拼接;排序字段等动态标识符走白名单映射。
- **并发靠约束。** 唯一性用唯一索引并映射约束冲突,不做"先查后写";更新并发状态用条件更新或事务。
- **事务边界显式。** 一次业务操作内的多次写入在同一事务里;事务内不做网络调用。
- **迁移向后兼容。** schema 变更带迁移文件,可重复执行;破坏性变更需显式评审并说明回滚路径;新访问路径带索引评审。

## 外部调用与配置

- **外部调用有超时、取消与重试预算。** 重试只用于可安全重复的操作,并明确重试主人;嵌套重试要合并预算而不是相乘。
- **配置在启动时校验。** 缺失或非法的配置立即失败并说明修法,不要静默回退到默认值;部署差异进环境变量或配置,不写死在代码里。
- **错误响应不泄漏内部细节。** 对外只给稳定的错误码与可操作的摘要;堆栈、SQL、内部路径进日志,并带 request id。
- **日志不放敏感字段。** 凭据、令牌、密码与个人数据永不落日志。
