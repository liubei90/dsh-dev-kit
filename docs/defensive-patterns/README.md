# 防御模式(Defensive patterns)

本目录的每一条都是**实现前先读、评审时强制执行的规则**：写成"必须成立什么，以及它防住哪类缺陷"。每条说明要求、评审判断条件、边界与例外由谁批准，并给出正确与错误示例。改哪类 artifact，就先读对应的那一页。

## 为什么是这些规则

五条习惯覆盖了下面的绝大部分内容，每一页都是它们在某一类 artifact 上的应用：

- **让正确性显式化。** 把正确性写进结构——命名清晰的调用点、显式的生命周期、显式的条件与类型——而不是事后用时序去补偿。
- **只保留一个真相来源。** 一份数据只有一条读路径，一个事实只有一个家，共享状态只有一个主人。
- **通过已注册的接缝扩展。** 新能力去注册；已有载体停止长新逻辑，而不是在里面分叉。
- **变更面等于评审面。** 一次变更只携带其声明的行为改变所需的行；迁移搬运代码而不是重写；性能敏感改动自带测量。
- **要求证据。** 结论可证伪、可复算——改前改后测过，或被门禁钉住——而不是靠手工同步。
