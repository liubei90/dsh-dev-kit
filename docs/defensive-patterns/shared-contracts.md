# 共享契约与包边界

适用于 `packages/shared`、各包的导出与构建面,以及跨进程的契约。

## 契约单一来源

- **DTO、校验与错误码只出现在 `packages/shared`。** 服务端与客户端都从它导入;消费端不手写与后端重复的模型类型,后端也不复制前端的展示模型。
- **契约变更同 PR 改两端。** 字段、校验规则或错误码变化时,服务端、客户端与测试在同一次变更里对齐;兼容性承诺写进契约文档。
- **错误码是稳定标识。** 机器读取错误码,人读取文案;不要靠解析 `message` 做分支。

## 包导出与构建面

- **导出面与构建产物一致。** `package.json` 的 `exports`/`main`/`types` 必须指向实际产出的文件;发布或部署前验证入口可解析,而不是只在源码平面里通过。
- **源码平面与产物平面分开验证。** 静态检查走 `paths` 指向源码;产物平面检查走构建后的声明文件。两者不能互相代替。
- **依赖方向单向。** `apps/*` 之间不直接依赖;共享经 `packages/shared`;库不反向依赖应用。
- **依赖声明与运行时一致。** 只在构建或测试使用的包放 `devDependencies`;运行时需要的包放 `dependencies`。

## 跨边界类型与校验

- **在边界做运行时校验。** HTTP、队列、数据库、文件、worker 与进程边界校验外部值;同一进程内的类型化接口信任 TypeScript,不为已由类型保证的值添加兜底或敌意输入测试。
- **品牌类型承载不透明 id。** 跨边界 id 用 branded type,不用裸 `string` 与另一个 id 互换。
- **禁止用断言绕过边界。** 不新增 `as unknown` 或 `as any`;需要收窄时用校验函数返回类型化的值。

## schema 与迁移

- **schema 变更带迁移文件。** 迁移向后兼容、可重复执行;破坏性变更显式评审并说明数据迁移与回滚。
- **迁移改变的是存储,不是语义。** 迁移前后对同一可观察行为做验证;不要借迁移顺便改业务规则。

## 生成物

- **生成文件不手改。** 生成的目录、目录清单与类型产物由生成器产出;要改就改源头并重新生成,门禁校验新鲜度。
